# APEX Pre-H8 Audit & Remediation Register

> **Date:** 2026-08-09
> **Scope:** Exhaustive audit of the current APEX codebase (H1–H7) before H8.
> **Policy:** AUDIT → CLASSIFY → FIX → TEST → VERIFY → DOCUMENT. No H8 work.
> **Frozen core:** `Action`, `Execution`, `ActionTransition`, `ActionRepository`,
> `ActionApplicationService`, `ActionExecutor`, `ActionExecutionWorker` — verified
> byte-identical to the pre-audit baseline (`git diff` empty for all seven files).
>
> All issues below were classified, and every issue with a safe concrete fix was
> fixed, tested, and verified in this pass. Remaining items are listed in
> section 6 with explicit reasons.

## 1. Executive summary

The audit inspected the entire monorepo (packages: ai-core, analysis, contracts,
prompts, shared, config, design-tokens, ui; app: web), the API server, all
application services, repositories, database engine, verification strategies,
providers, security primitives, the dashboard, CI, and all documentation.

The most important findings were **cross-tenant data-loss** (upserts keyed by
`id` alone could delete another workspace's rows), **silent production
mock-downgrade paths** (unconditional `MockLLMProvider`, placeholder credentials,
mock analysis fallback on clone failure), **fabricated data flowing into H4
reasoning** (hardcoded `CRITICAL_PRODUCT_RISK` / `priorityScore: 5.0` decoration),
**fabricated UI evidence** (guessed file paths, timer-faked progress stages,
fabricated metric fallbacks), and **broken contracts** (non-deterministic
"deterministic" signal IDs, login overwriting workspace names, workspace-wide
metrics leaking across projects, duplicated pipeline execution).

All four gates pass after remediation: `pnpm type-check`, `pnpm lint`,
`pnpm test` (582 tests), `pnpm build`.

## 3. Frozen-core issues (NOT modified — documented only)

1. **`ActionExecutor` retry path is not atomic.** On retry scheduling it persists
   `saveExecution(execution)` and `save(action)` as two separate repository calls,
   while completion/terminal-failure paths use the atomic
   `persistExecutionOutcome`. Frozen; boundary coverage exists
   (`ActionExecutionWorker.test.ts` verifies retry behavior). A future
   repository-level transaction would fix this without changing the frozen
   contract.
2. **`ActionExecutor` emits `console.log('[EVENT] ...')`** instead of the
   structured `Logger`. Frozen; observability fix deferred.
3. **`ActionExecutionWorker` logs via `console.warn`** for per-action failures.
   Frozen.
4. **`redactSensitiveData` (in frozen `ActionApplicationService`) redacts
   `idempotencyKey`/`externalId`** in execution event logs; only the
   non-frozen `Logger` was refined (F33).
5. **`AuthRateLimiter` is single-process in-memory** — documented limitation of
   the supported single-process architecture.

All five are behavior-preserving observations; no frozen file was modified
(`git diff` empty for the seven frozen paths).
